Process — how a note is made

Seven phases. Every rated call goes through them. Oracle is the worked example here — most complete record, five method rules from one onboarding pass, central finding is a disclosure gap.

Phase 1 — Question file (pre-registration)

Every note starts as a question file: the thesis committed BEFORE research begins, with pre-registered sell triggers. Written past-tense to force specificity. Committed to git so the timestamp is external evidence.

Oracle's question file was committed 2026-09-13. The rating call that shipped 2026-09-13 in a rated state referenced this pre-registration. Rules M12 and M17 govern the position-disclosure discipline the question file enforces.

Phase 2 — Sources file with markers

Every quantitative claim in the shipped note carries an inline marker ([O04]) that resolves to a row in the sources file. The provenance check (Gate 1) enforces set-equality: every marker in the note has a row, every row is referenced.

Phases 3-4 — Research + model

Primary-source read. Model built in models/<TICKER>/ with drivers.yaml + actuals.yaml. Every driver either sourced (TIER 1) or ESTIMATE-with-rationale.

Phase 5 — Publication

Ship gate runs 16 checks. Note commits only if all pass. State/current.md rewrites automatically.

Phase 6 — Monitoring

Registered EDGAR watch. New filings on covered names produce work orders. Kill criteria evaluated at each earnings print.

Phase 7 — Calibration

Every call receives a probability at open. At evaluation date, direction / magnitude / mechanism scored separately. Withdrawn-on-thesis-error scores as a miss on direction — the finding is not grounds to erase the forecast.
